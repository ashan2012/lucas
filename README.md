# zige · 拼读小卡片 → 田字格笔顺卡

输入一张小学生拼读小卡片（拼音 + 汉字）的照片，自动识别出词语，并为**每一个汉字**生成田字格笔顺图：一笔一格逐笔演示，再给出编号全图和空白练习格。

```
卡片照片 ──OCR──▶ 词语表 ──笔顺数据──▶ 田字格页面 ──▶ PNG / PDF / HTML
```

## 输出内容

以示例卡片（26 个词语、41 个不重复汉字）为例，输出目录结构：

```
out/
├── pdf仓库/                           所有合订 PDF 都收在这里
│   └── 每日拼读练习小卡片第3天.pdf       本次生成的合订 PDF，A4 打印
└── <卡片名>/
    ├── 00_cover.png                   总览：所有词语 + 拼音
    ├── 01_画画.png                    第 1 个词语的笔顺页（按卡片序号命名）
    ├── 02_打鼓.png
    ├── ...
    ├── 25_哈密瓜.png
    ├── chars/
    │   ├── 画.png                     单字强化页：笔顺 + 描红 + 自己写一写
    │   ├── 瓜.png
    │   └── ...（每个不重复汉字一张）
    ├── parsed.json                    识别结果，可手工改后重新渲染
    └── index.html                     网页预览（可直接用浏览器打印）
```

页面内容：

* **词语页**（每个词语一张）
  * 顶部：词语、拼音、卡片标题
  * 逐笔条：第 1 格只有第 1 笔，第 2 格有前 2 笔……**最新一笔标红**，一眼看出这一笔从哪起、往哪收
  * 编号格：灰色字形上叠加红色笔顺编号（自动避让，密笔字也不会糊成一团）
  * 练习格：空白田字格
  * 词语里重复的字（如「画画」）只画一次，避免重复
* **单字页**（每个不重复汉字一张）
  * 笔顺条 + 描红（浅灰字帖）+ 空白练习行
* **总览页**：整张卡片的词表，方便对答案

## 环境要求

| 项目 | 要求 |
| --- | --- |
| 系统 | macOS（OCR 使用系统自带 Vision 框架，无需下载模型） |
| Swift | 需要 `swiftc`，即 Xcode Command Line Tools：`xcode-select --install` |
| Python | 3.9+（macOS 自带 3.9 即可） |
| 依赖 | `pillow`、`pypinyin`（`run.sh` 会自动建 venv 安装） |
| 网络 | 仅首次需要：下载每个字的笔顺数据，之后缓存在 `cache/strokes/`，可全程离线 |

## 快速开始

最简单的方式：

```sh
./run.sh 卡片照片.jpg
```

`run.sh` 会自动创建 `.venv`、安装依赖，然后调用 CLI。也可以手动执行：

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m zige 卡片照片.jpg
```

运行后会打印识别到的词语表，页面写到 `out/<图片文件名>/`，合订 PDF 统一归档到 `out/pdf仓库/`。

## 常用参数

```
zige IMAGE [选项]
zige --from-json out/xxx/parsed.json [选项]     # 改正识别结果后重新渲染
```

| 参数 | 说明 |
| --- | --- |
| `-o, --out DIR` | 输出目录，默认 `out/<图片文件名>` |
| `--pdf-dir DIR` | 合订 PDF 的存放目录，默认是输出目录同级的 `pdf仓库/`（即 `out/pdf仓库/`） |
| `--cell N` | 田字格边长（像素），默认 200；打印建议 200，屏幕预览可用 120 |
| `--scale N` | 超采样倍数，默认 2；笔画边缘更平滑，`--scale 3` 更细腻但更慢 |
| `--max-cols N` | 每行最多几格，默认 7 |
| `--practice N` | 每个字的空白练习格数量，默认 2，`--practice 0` 可关闭 |
| `--only 1,3` | 只渲染指定序号的词语（序号见输出表格），便于补打某几页 |
| `--no-pdf` | 不生成合订 PDF |
| `--no-char-pages` | 不生成 `chars/` 单字页 |
| `--offline` | 只用本地缓存，不联网 |
| `--workers N` | 并发下载笔顺数据的线程数，默认 8 |
| `--dump-ocr` | 只打印 OCR 原始文本行，用于排查问题 |
| `--debug` | 打印「行结构」：哪些行被判定为拼音行 / 汉字行 / 忽略 |

常用组合：

```sh
# 只补打第 5、6 个词语，快速预览
./run.sh 卡片.jpg --only 5,6 --cell 120 --no-pdf

# 改完 OCR 结果后重新出整套（离线可跑）
./run.sh --from-json out/卡片/parsed.json --offline
```

## 拼图游戏

把卡片里的词语变成给孩子玩的拖拽拼图，**整份材料就是一个 HTML 文件**（样式、脚本、笔顺数据全部内联），双击就能玩，不用起服务。

```sh
.venv/bin/python game/build.py                       # 全部卡片 -> out/游戏/拼音笔顺拼图.html
.venv/bin/python game/build.py --card 第3天           # 只做一张卡片
.venv/bin/python game/build.py --word 画画            # 只做一个词语（调试用）
```

脚本会扫描 `out/*/parsed.json`，把每张卡片里的每个词语都做成一个**关卡**；`pdf仓库` 里 4 张卡片的 100 个词语就是 100 关，默认按卡片、按页码顺序连成一串，关卡下拉框按卡片分组。

页面分三栏：

| 区域 | 内容 |
| --- | --- |
| 左「拼音口袋」 | 26 个拼音字母 + 四个声调（ˉ ˊ ˇ ˋ），可无限取用 |
| 中「拼一拼」 | 上面是拼音虚格（**不给提示，孩子自己拼**）；下面是田字格，格子里的整字是**灰色描红底**；底部是「看演示」按钮 |
| 右「笔画口袋」 | 当前汉字的全部笔画，**打乱顺序**，另外混入 **5–7 个别的字的笔画**当干扰项 |

规则：每拼对一块（字母 / 声调 / 笔画）**+2 分**；笔画必须按书写顺序拖，顺序错了会被退回并提示「现在该写第 N 笔」；声调要先放字母再放调号；拖到错误笔画会被退回；全部拼完后弹出结算面板（本关得分、本关用时、本卡用时、一次就对的比例、累计分），可直接「下一关」接着闯。

- **看演示**：点一下，页面会用动画从口袋里“拖”一遍当前关卡——先拼拼音、再按笔顺写笔画；演示不计分也不计时，放完自动清空等孩子自己来。
- **提示**：闪一下下一步该拖的那块（字母 / 声调 / 笔画）。
- **整卡总计时**：关卡条上的「本卡用时」累加同一张卡片里每一关的时间，换到另一张卡片自动归零；结算面板里也会再显示一次。
- **错题重练**：哪一关拖错过，就自动收进关卡条右侧的「错题重练 N」；点一下按错题顺序重打一遍（关卡标签变成「复习 1/N」），这一遍一次没错就把它移出错题本，复习完点「回到闯关」回到原来的进度。
- **错题本跨天保留**：错题记在浏览器本地（localStorage，按「卡片|词语」存，重新生成页面也不会错位），第二天打开还在；旁边的「清空」要点两下才生效，防止孩子误碰。
- 一次只激活一个字：前一个字拼好，右侧才会换成下一个字的笔画；三字词（如 哈密瓜）会自动收窄田字格，整行都在卡片里。

## 工作原理

1. **OCR（macOS Vision）**
   `zige/swift/vision_ocr.swift` 在首次运行时由 `swiftc` 编译成一个小工具，输出带归一化坐标的文本行。
   Vision 认汉字几乎不出错，但拼音声调经常乱码（`huà huà` 会变成 `hud hud`）。
   *因此拼音不采用 OCR 结果，只把汉字交给下一步。*

2. **版面还原（`zige/layout.py`）**
   按垂直中心把文本行聚类 → 多数票判定每行是「拼音行」还是「汉字行」→ 每个汉字行与**紧邻其上的拼音行**配对 → 按水平中心距离配对单元格（容忍 OCR 框的小偏移）。
   标题、`3.g k h` 这类课次标记、页脚「我读了（ ）遍」都会被过滤掉。

3. **拼音生成（`zige/pinyin_util.py`）**
   用 `pypinyin` 按词语上下文重新生成，声调一定正确，多音字按词组判定：
   贺卡 → `hè kǎ`、可乐 → `kě lè`、花朵 → `huā duǒ`。
   OCR 的拼音只当**弱提示**：只有当它恰好是某个字的合法读音、且与词典结果不同时才会采纳，并打印 `!` 提示，例如：

   ```
   ! “可乐”第2字按卡片采用 yuè（词典默认 lè）
   ```

4. **笔顺数据（`zige/strokes.py`）**
   每个字的 JSON 里有两样东西：`strokes`（每一笔的**轮廓路径**）和 `medians`（每一笔的**运笔轨迹**，用来定位编号）。
   自带一个精简的 SVG 路径解析器（只支持 hanzi-writer 用到的 `M/L/Q/C/T/Z`，含绝对与相对指令），把路径拆成多边形后用 Pillow 填充。
   坐标做统一的 `y_img = 900 - y_data` 翻转 + 以 (520, 500) 为基准等比缩放，**不做逐字归一化**，所以「一」和「蘑」在格子里的大小关系跟真实字形一致。

5. **渲染（`zige/draw.py`）**
   所有几何按最终像素计算，再以 `--scale` 倍超采样绘制、LANCZOS 缩小，得到平滑的笔画边缘（Pillow 的多边形填充本身没有抗锯齿）。
   笔顺编号会沿笔画切向 / 法向逐步试探，直到不再与其他编号重叠。

## 识别不对怎么办

`parsed.json` 就是为此准备的：

```json
{
  "title": "每日拼读练习小卡片（第3天）",
  "subtitle": "3.g k h",
  "words": [
    { "hanzi": "画画", "pinyin": "huà huà", "pinyin_ocr": "hud hud" }
  ]
}
```

改 `hanzi` 后重新渲染即可，`pinyin` 留空会自动重新生成：

```sh
./run.sh --from-json out/卡片/parsed.json
```

排查建议：先用 `--dump-ocr` 看原始文本，再用 `--debug` 看行分类。若是竖排卡片、或拼音在汉字下方，版面判定会失效，此时直接用 `--from-json` 手写词表最快。

## 其他注意事项

* **缺笔顺数据**：GB2312 之外的生僻字可能没有数据。该字会在页面里显示提示文字，其余页面照常生成，退出码为 0；命令行会汇总提示。
* **OCR 偶发失败**：Vision 偶尔报 `nilError` / `Error loading network`，Swift 端已内置三级降级（accurate+语言 → fast+语言 → accurate+自动语言），Python 端再重试一次；仍失败时重跑即可。
* **首次运行较慢**：要编译 Swift 工具（约几秒）并下载每个字的笔顺数据，之后走缓存。
* **输出会被清理**：每次渲染会先清掉输出目录里旧的 `*.png` / `*.pdf`，避免 `--only` 之后残留旧编号的页面。手工改过的 `parsed.json` 不会被动。`pdf仓库/` 里的旧 PDF 不会被批量删除，同名卡片重新生成时直接覆盖。

## 测试

```sh
.venv/bin/python -m unittest discover -s tests -v
```

33 个用例，覆盖版面配对、多音字判定、SVG 路径解析、坐标映射、页面渲染、JSON/HTML/PDF 导出，以及一次「JSON 进 → 页面出」的完整构建。
OCR 用合成文本行代替，因此不需要图片、不需要网络；渲染类用例在笔顺缓存为空时会自动跳过。

## 目录结构与代码导读

```
zige/
├── cli.py          命令行入口、参数校验、退出码
├── pipeline.py     编排：图片/JSON → 词语 → 预取 → 渲染 → 导出
├── ocr.py          Vision 调用、坐标换算、Swift 工具编译缓存
├── layout.py       行聚类、行分类、单元格配对
├── pinyin_util.py  pypinyin 生成 + OCR 交叉校验
├── strokes.py      笔顺数据下载/缓存、SVG 路径解析、坐标变换
├── draw.py         田字格、逐笔条、单字页、总览页
├── export.py       PNG / PDF / HTML / JSON
├── fonts.py        系统中文字体探测（含声调符号）
├── config.py       常量与可调参数
└── swift/
    └── vision_ocr.swift
```

退出码：`0` 成功；`2` 参数/OCR/JSON 错误；`3` 卡片里没找到词语；`4` 笔顺数据不可用。
